# 发布与收录

## 发布

插件发布在 GitHub 或 Gitee 的**公开**仓库里，有两种放法：

- **一个仓库一个插件**：`folio-plugin.json` 放在仓库根目录。用户粘贴仓库首页的链接就能装。
- **一个仓库多个插件**：每个插件一个文件夹。用户粘贴文件夹的链接：`https://github.com/作者/仓库/tree/main/插件文件夹`。

发布前：

```bash
folio-plugin validate .
```

给仓库加上 `folio-plugin` 话题（GitHub 仓库页右侧 About › Topics），方便别人搜到。

### 也可以发 .zip

```bash
folio-plugin pack .            # 生成 <id>-<version>.zip
```

压缩包里只有清单和 `files` 列出的文件。可以放在 GitHub Releases 或任何地方让用户下载；用户在页间里点「安装 .zip…」或者把压缩包拖进插件页就能装。用户直接用 GitHub 的「Download ZIP」下载整个仓库也能装（仓库里只有一个插件时）。

## 更新

1. 改 `version`（比如 `1.0.0` → `1.1.0`），推送到仓库。
2. 从链接安装的用户在插件卡片上点「检查更新」就能看到新版本。页间装的是某一个 commit，作者推送了新代码，用户不点更新就不会变。
3. 新版本比旧版本多要的权限（网站、写入文件夹、工具、脚本、联网搜索）会在更新时单独标红，让用户再确认。所以**只在确实需要时增加权限**，并在更新说明里讲清楚为什么。

`id` 发布后不要改：页间按 `id` 认插件，改了就是另一个插件，用户的设置和运行记录都对不上。

## 收录到插件目录

页间「设置 › 插件 › 浏览插件目录」读的是这个仓库里的 [`community-plugins.json`](../community-plugins.json)。想让你的插件出现在这里：

1. Fork 这个仓库。
2. 在 `community-plugins.json` 的 `plugins` 末尾加一项：

   ```json
   {
     "id": "my-plugin",
     "name": "我的插件",
     "author": "你的名字",
     "description": "一两句话说明它做什么。",
     "repo": "https://github.com/你/仓库/tree/main/my-plugin",
     "tags": ["日报", "RSS"]
   }
   ```

   - `id` 必须和插件清单里的 `id` 一样，而且目录里没有重复。
   - `repo` 是仓库或插件文件夹的链接（GitHub / Gitee）。
   - `tags` 可选，最多 5 个，每个最多 16 个字。
3. 提交 Pull Request，按模板勾选检查项。CI 会读取你仓库里的清单，用和页间一样的规则检查。
4. 维护者按 [收录审核标准](review.md) 看一遍，通过后合并。合并后半小时内，页间里就能搜到。

页间从目录安装时会核对：仓库里插件的 `id` 必须和目录里写的一样，否则拒绝安装。安装前照样会列出它要的权限，装的是当时那个 commit。

### 从目录移除

作者可以随时提 PR 把自己的插件移出目录。插件出现安全问题、长期无法安装，或者和描述严重不符时，维护者也会移除。已经安装的用户不受影响：插件照常运行，从链接装的也照常能检查更新。
